# Common row factor observations

The comparison JSON records contain the existing fresh-module runner's six
adjacent AB/BA pairs, import-only baselines, source hashes, environment, routes,
compiler output and medians. The observation JSONL files retain each completed
build independently, including baseline observations. Status records give the
supervisor's deadline and elapsed time. The Python adapters show the exact
bounded subsets and stop on the first failure or timeout.

`row-factor-comparison` measures commit e7cd58bc7. `row-factor-refined-comparison`
and `row-factor-acceptance-comparison` measure commit 2646dd6ee after explicit
applications and shared proof payloads. Keep these experiments separate; do
not pool samples or substitute later observations for earlier losses.

`row-factor-attribution`, `row-factor-components-final` and `entry-orientation`
are focused component diagnostics, not independent timing comparisons. Their
worktrees include temporary inspectors; original output and environment are
retained. `row-factor-components` retains the initial inspector failure before
it was corrected to unwrap the expected-type hint. Its failure supplies no
component timing evidence. No instrumentation is installed in library sources.

The row-factor route bypasses polynomial crossover tables. These samples must
not fit tree/list tables or justify claims about arbitrary polynomial matrices.

`kernel-folds` records the general forced-tree diagnostic after primitive
recursors replaced the bounds folds. `Inspect.paired.lean.txt` is the inspector
fragment consumed by the capture adapters; it is retained as data, not a build
target. Component checks in one module are order-sensitive, and do not establish
the strict general-tree attribution bars described in the performance report.
