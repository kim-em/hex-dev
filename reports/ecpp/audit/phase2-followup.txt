## Remaining findings (none blocking)

**L1. Low-medium: the SPEC contract. `Resource.pointRetries` can never be the final diagnostic.**
- **Location:** `Search.lean:134-136` together with `:281` and `:324`.
- **Evidence:** Every node that records `pointRetries` either succeeds or ends with `unresolved n .portfolio` at the same subject, and that rule replaces it. The tests pin this: `exhausted hard {pointRetries := 0} .portfolio` and `rejected`.
- **Why it matters:** The SPEC (lines 236-239) says diagnostics *distinguish* exhausted local point retries from the complete portfolio. The rule "portfolio at the same node supersedes local retries" is the code's addition, not the SPEC's.
- **Fix, either:**
  - (a) At portfolio end, report `⟨n, pointRetries⟩` when no candidate at this node reached a child and at least one twist ran out of retries; or
  - (b) Amend the SPEC so per-twist retry exhaustion counts as rejecting that candidate, and drop the constructor.

**L2. Low: priority uses subject size as a stand-in for depth.**
- **Location:** `Search.lean:135`.
- **Evidence:**
  - `n < e.subject` also holds for unrelated siblings. If two children both fail, the smaller one overrides an earlier `nonresidueRetries`, but a larger one does not, so the reported failure depends on numeric order rather than on the tree.
  - The `childRetry` test uses a synthetic "ancestor" `hard + 2`, so no real parent-to-child failure is exercised.
  - In stateful use, `stats.unresolved` carries over between calls, so a later failing call reports an earlier call's frozen diagnostic.
- **Fix:** Record the depth with each diagnostic, and document that callers should reset `unresolved` between calls (or provide a helper that does). Add one real recursive failure test.

**L3. Low: conversion's subject binding is vacuous and isn't stated as a theorem.**
- **Location:** `Import.lean:244`, `:372-374`.
- **Evidence:** `checkAt cert.subject cert` is a tautology. It is equivalent to the intended check only because `convertRows` happens to build row 0's `n`. Consumers (`Compact`, `Native`, `Elab`) re-check `checkAt n` themselves, so soundness is unaffected.
- **Fix:** Bind to `input.rows.head?.map (·.n) |>.getD input.endpoint`, state that in `convert_ok`, and add `convertText_ok` and `convertCounted_ok` corollaries.

**L4. Low: text-level failures report row 0.**
- **Location:** `Import.lean:313-318`.
- **Evidence:** A digit-limit, bad-character, nesting or JSON-syntax error inside row 7 reports `row = 0`, which looks the same as "row 0 failed". The SPEC asks for enough location to identify the failing row (line 178).
- **Fix:** Give `ImportError` a location type that distinguishes the input text (byte offset), a row and the endpoint.

**L5. Low: minor items.**
- The `convertCounted` docstring says fuel is "capped", but the code rejects fuel over the limit (`Import.lean:352-353` vs `:359`).
- For a directly constructed `PariCertificate`, the cheap row arithmetic (exact division, q chaining) still runs only after the endpoint search. Parsed input already checks the last row's division.
- A full memo aborts a found success with `.memo`. This is consistent with the SPEC's allocation semantics, but stopping caching would be gentler. In stateful use, a memo hit can also return a chain deeper than the remaining depth.
