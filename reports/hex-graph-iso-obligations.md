# Structured-search correctness

`HexGraphIso/Nauty/Policy/KeyComplete.lean` and `Complete.lean` export the whole-engine theorems:

- `Engine.canonSpecKey_eq_tracedKey`: for a nonempty coloured graph, the
  structured engine returns the complete specification key.
- `Engine.generators_complete`: every colour-preserving automorphism is
  generated by the engine's own checked output trace, including on empty
  graphs.

Neither theorem takes local-rule or legacy-search correctness assumptions.
`MaxCombine.rules` supplies every decision rule. `Complete` also imports
`Policy.Result`, which proves canonical-label reach, permutation and colour
preservation, row reconstruction, generator validity, and traced-result
agreement. The library umbrella imports `Complete`.

The empty graph has a separate certificate case. Its specification key has
empty codes, while its traced key has a singleton sentinel code. Key equality
therefore retains the positive-size hypothesis. Generator completeness has
no such restriction.

## Maximum and nonlocal returns

`Max.key_eq` initializes the actual root and applies the generic recursion's
call contract. Its adequate-fuel input excludes exhausted normal runs.
`Max.first_leaf` installs the first discrete leaf's complete key;
`Max.finish` turns an exhausted cursor into coverage of every original
child. The remaining rules cover internal preparation, both automorphism
verdicts, better and rejected leaves, child visits, and orbit skips.

A suspended frame contains its actual node entry and preceding code prefix.
`Frame.Witness` permits a subtree bound or a universal extension bound after
that frame's next refinement code. `Witness.resolve` converts either into
coverage at the actual receiver. Intermediate sweeps transport the witness;
they do not claim to have covered the skipped subtree at their own level.

The cheap return retains the exact target `noncheaplevel - 1`.
`NodeInput.cheap_witness` propagates the emitting node's bound through cheap
suspended parents. Each parent either already has a negative comparison
bound or has the same full specification key as its selected child.
This uses small-cell geometry and actual refinement/individualization
states, including reordered parent labellings.

`SweepInput.push` constructs the smaller child's input.
`SweepInput.receive_call` incorporates its returned coverage, applies the
actual filters, recovers the parent, and constructs the exact resumed
cursor and live set. `Max.visit` combines smaller child and suffix contracts.
The same contract retains stabilization of emitted generators at each
surviving first-path ancestor. The code-two coset-index exit uses that
stabilization and an earlier child's ranked coverage.

## Generation

`FirstComplete.firstPath_complete` obtains the first-path return and a
reference occurrence with its target sequence and uniformity boundary.
`ReferenceComplete.reference_complete` follows that occurrence through
actual off-path calls and filtered sweeps. Its conclusion retains the
emitting first/canonical scatter or coset-index orbit witness.

`GeneratedTrace.Realizes` interprets recorded arrays as words in an arbitrary
containing generator list. Child and suffix trace inclusion are proved at
their calls. `GeneratedHead.firstPath_cover` constructs generated carriers
for every image of the guiding child using the actual sibling visits and
orbit skips. No coverage premise is assumed at the root.

A short return to a first-path sibling receiver is impossible: its target
must differ from `gcaFirst`, while that receiver equals `gcaFirst`. Both
filters therefore occur inside the off-path matching-reference argument.
Checked geometric carriers preserve reference occurrence there, and the
actual returned scatter supplies the generated image. This avoids assuming
that every implicit workspace pair itself has a generated carrier.

`GeneratedComplete.firstPath_generates` combines the actual smaller guiding
child's generation theorem with the actual sweep's image coverage through
`Perm.Generated.of_stabilizer`. `GeneratedTerminal.first_terminal` supplies
the discrete case. `GeneratedRoot.root_generates` constructs all nonempty
root inputs and extracts permutations from the engine's emitted trace;
`zero_generates` handles size zero. The smaller maximum contracts these
proofs consume are supplied by `MaxCombine.rules` in `Complete`.

## Dependencies and optimization locality

Reusable reference, occurrence, transport, cursor, carrier, and stabilizer
lemmas live in `Nauty/Generation/` and `Nauty/Invariant/`. Automorphism-array
admission lives in `Autom.lean`; point-stabilizer orbits live in `Orbit.lean`.
The import closure of `Policy.Complete` contains no `Nauty/Correct/`, `Ops`,
or `AutTrace` modules. The old traversal proof is not relocated into these
mathematical modules.

The bounded-workspace experiment and its normal-root fixture are documented
in [hex-graph-iso-locality.md](hex-graph-iso-locality.md). Scanning only the
newest 32 pairs changes the fixture from 168 to 712 visited nodes while
retaining its canonical key and 11 generators. Both variants compile
through the new maximum and generation rules with local filter-lemma
changes. The legacy proof needs equally local changes: this establishes
locality parity for this experiment, not an exclusive advantage or speedup.
The delivered production filter remains the full scan.

## Public integration

The public canonicalization and generation APIs use the structured engine.
`Cert/Certify.lean` derives certification totality from `KeyComplete`, while
`AutComplete.lean` obtains public generator completeness from `Complete`.
`Policy/PublicResult.lean` supplies the reach and result facts consumed by
certificate totality. `CertTotal` reuses the existing translator's candidate
totality theorem instead of duplicating it.

`Search/Search.lean` contains the engine and its nauty correspondence table.
`Search/State.lean` retains input/output representation and primitive
transitions used by the mathematical view. The literal recursive traversal,
`Nauty/Correct/`, `Invariant/Incumbent`, `Invariant/Closure`, and `Cert/TraceAgree`
are deleted. `Invariant/Reach` retains primitive transition and root
initialization facts; generic recursion supplies whole-call reach.
Pure child coverage and primitive `SearchSt` lemmas remain shared.

Both libraries, registered tests, conformance, and the manual build. The
6,233 emitted fixture records match the committed corpus byte for byte and
pass the nauty oracle, including 205 automorphism-group cases. The extended
32,798-case campaign also passes the oracle. The wrapper twin agrees over
all three corpora. These checks cover the same engine through its public
and direct entry points; they are not two independent search algorithms.

The conformance guards retain explicit fuel exhaustion, workspace overwrite,
cheap admission, both short flags, and canonical/coset return cases. Root
axiom guards check key equality and generation through the standard logical
axioms. Delivery also requires the fresh chungus2 sweep and CI checks; the
mathematical results do not substitute for performance validation.

## Performance validation

The chungus2 cactus sweep is recorded under fingerprint `4fa1958f160d`,
including runtime and pairs data, tactic timings, manifest, metadata, figures,
and the per-node fit. It passes the existing exponent margin of 0.2.
The tactic leg solves every previously solved case; `neg-circ96-vs-2circ48`
retains its timeout, while `neg-paley61-vs-circulant61` finishes in 85.91 s.

The [direct-engine timing run](bench-results/hexgraphiso-engine-4a7c8747f686-chungus2.jsonl)
uses CPU 91 and the same 98 cases as the spike's stored three-trial median
`hexgraphiso-engine-ddc22cf4b645-chungus2.jsonl`. Every node count is unchanged.
The geometric mean of current/spike `eng_ns` is 1.0012; the largest individual
ratio is 1.0243. This is one current run against archived measurements, with
observed engine costs effectively unchanged. The current engine also passes
the per-node exponent check against nauty with margin 0.2.

The benchmark retains its historical `lit_ns` and `eng_ns` columns. They now
measure public and direct wrappers around the same engine. Their comparison
is a wrapper check; the archived `eng_ns` values provide the comparison with
the spike. The nauty timing baseline differs between these records, so ratios
to nauty are not used to infer a change in the engine's execution time.
