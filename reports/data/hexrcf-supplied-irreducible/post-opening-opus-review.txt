## Concerns

1. **Medium (usability): instances in any other form are silently ignored.**
   - **Where:** `CommonTactic.lean:37-38`.
   - **Reason:** Lookup runs at instance transparency against `DensePoly.ofCoeffs (List.toArray [mkIntLit …])`. The repo's usual style is `abbrev polynomial := DensePoly.ofList [...]` (`SquareTwo.lean:19`, `CubeTwo.lean:20`), and the report itself says `ofList` did not match. Such an instance is skipped, the producers run, and the user sees "no checked irreducibility witness for this common field" with no hint that an instance existed in the wrong form.
   - **Fix:** On that terminal producer failure, have the message print the exact target `CheckedIrreducible <pExpr>` and say instances must use the `ofCoeffs` literal. Optionally also try the `ofList` spelling.

2. **Low to medium (test robustness): `supplied` is a global, unscoped instance.**
   - **Where:** `conformance/HexRCF/SuppliedIrreducible.lean:156`.
   - **Reason:** `CertificationProofs.lean:152-154` expects "no checked irreducibility witness" for exactly this octic. It stays green only because it doesn't import this module. Any future module importing both would flip the expected refusal.
   - **Fix:** Make it a `scoped instance` and add `open scoped Hex.RCF.SuppliedIrreducible` in the consumer. That also shows the opt-in pattern.

3. **Low: the runtime-binding check is lopsided.**
   - **Where:** `CommonTactic.lean:39-40`.
   - **Reason:** The check only runs on the supplied branch. In the only internal caller (`prepareField`), `pExpr := zpolyExpr p`, so it can never fail there. The producer branch doesn't bind `p` to `pExpr` at all; a mismatch only surfaces as a `decide` failure.
   - **Fix:** Move the check above the `if`, so the public `certify` contract is the same on both branches.

4. **Low: rejection messages are confusing.**
   - **Where:** `CommonTactic.lean:41`.
   - **Reason:** Rejections read "rcf: handler …CommonTactic.certify proposed a proof using forbidden axiom sorryAx". That doesn't tell the user their own instance was rejected, or which one.
   - **Fix:** Catch and rethrow as "rcf: supplied `CheckedIrreducible` instance `<const>` for `<pExpr>` rejected: …", using `proof.getAppFn.constName?`.

5. **Low: the negative controls accept any exception.**
   - **Where:** `SuppliedIrreducibleProofs.lean:43-46` and `54-57` use `observing?` and only check `isNone`.
   - **Reason:** Any exception passes, not just the intended rejection. The accepted control at lines 31-36 also doesn't show that `supplied` was reached; only the `positive` evidence check does.
   - **Fix:** Match the error text ("different runtime polynomial", "sorryAx"), and check that the accepted result's auxiliary theorem refers to `supplied`.
