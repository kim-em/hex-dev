**`Core.prependError`: verified against the v4.35.0-rc3 source**
- **Only ordinary errors are rewritten** (`Lean/CoreM.lean:866-882`). Its `try … catch` goes through `Core.tryCatch` (`CoreM.lean:806-813`), which rethrows interrupts and heartbeat/recursion-depth errors before the handler runs. Those keep their tags, so `isRuntime`/`isMaxHeartbeat` still recognise them upstream. Wrapping them would have turned them into plain errors.
- **Rejection stays terminal.** The handler rethrows, nothing in `certify` catches, and state changes are not rolled back, the same as before.
- **Kernel budget failures get the wrong label (optional fix).** The kernel's "deterministic timeout" and "deep recursion" are untagged plain errors (`Lean/Message.lean:890-892`). They will now read "supplied CheckedIrreducible instance … was rejected", although they are budget failures, not rejections. They were already terminal, so this only affects the label.
- **Instance search is correctly left unwrapped.** `synthInstance?` turns resource failures into a plain "failed to synthesize" error (`Meta/SynthInstance.lean:686-692`). That error is uncaught in `certify`, so it is terminal and not reported as a rejection. This matches the new SPEC sentence.
- **Blank line (cosmetic).** The prefix ends with `:\n` and `indentD` adds its own line break, so the message shows a blank line before the indented inner error. Dropping the `\n` fixes it.

**Caller restoration doc: accurate.** The only production call (`CommonTactic.lean:545`) is reached through `handle` → `dispatchHandlers`, which restores state unless the result is a proof (`HexRCF/Tactic.lean:139-146`), and through `prepareCached`, which also restores (`CommonTactic.lean:906-922`).

**Concerns (small, non-blocking)**
1. **The negative test is tighter but not exact** (`SuppliedIrreducibleProofs.lean:79-80`). It checks the prefix plus the substring `sorryAx`. The report calls this "the instance-specific forbidden-axiom diagnostic", but the test doesn't check for `forbidden axiom sorryAx`. Checking that substring would make it match the claim. I see no realistic false pass today: the kernel accepts `sorry`, so `sorryAx` can only come from `checkAxioms`.
2. **The SPEC's ordering is slightly wrong** (`hex-rcf.md:1416`). "The frontend first reuses a matching … instance" leaves out that an already matched source-leaf proof wins, and `certify` is never called in that case (`CommonTactic.lean:531-545`). The manual qualifies this as "For a new common polynomial", and the SPEC should too.
3. **The new import comment overclaims** (`SuppliedIrreducibleProofs.lean:10-11`). `CertificationProofs` doesn't import the supplied fixture, so importing both here cannot "alter the legacy module's environment". The only behaviour checked with both imported is that the scoped instance is inactive (lines 22-27). Either reword the comment to that, or run the degree-eight legacy refusal in this environment to back the claim.
