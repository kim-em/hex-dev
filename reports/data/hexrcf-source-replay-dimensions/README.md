# Selected-source packet observation record

[The report](../../hexrcf-source-replay-dimensions.md) explains the measured scope and limitations. `context.json` binds the clean Hex checkout, toolchain, 449 compiled imports (none Mathlib), local source hashes, four driver/generator/collector hashes, executable hash and all 440 completed observations. `manifest.json` binds every retained artifact. No executable binary is committed.

Run `python3 reports/data/hexrcf-source-replay-dimensions/verify.py` from a checkout containing the historical source commit. `--check-head` additionally compares the recorded local computational sources with this checkout. This verifies record consistency, raw result hashes, the complete fixed schedule, summaries, independent declared axes and selected-row DAG sizes. It does not rerun Lean or prove checker soundness; ordinary-kernel proof evidence remains in the separate source/quotation records.

`inputs.tar.gz` stores all 22 byte-exact packets and their eleven-column manifest: name, varied axis, parameter, defining degree, query count, query denominator exponent, dyadic precision, predecessor depth, bytes, unique row nodes, expanded row references. The last two columns exclude descriptor and predecessor graphs. `samples.tar.gz` stores every raw export, stdout/stderr and original collection context. Empty outputs are retained. `preparation.tar.gz` stores all completed build/control attempts, failed-source snapshots where available, compiler setup records, final negative inputs and frozen pre-collection snapshots. Failed setup attempts are not passing evidence; their corrections are explained in the report. `collection.log.gz` retains the actual successful systemd completion and memory accounting.

The exact historical external project configuration is `lakefile.lean.txt`; it contains unrelated earlier targets that were not built for this study. Rebuilding only this study needs a separate scratch project with `require Hex from "/path/to/the/matching/hex/checkout"`, `lean_lib SourceReplayDriver`, `lean_lib SourceReplayMatrix`, `lean_lib SourceReplayControls`, and a `source_replay_bench` executable rooted at `SourceReplayBench`. Copy the driver, generator, controls and benchmark snapshots to their corresponding `SourceReplay*.lean` names. Use the recorded toolchain and dependency revisions in `lake-manifest.json`; LeanBench is supplied by the Hex dependency. Build via Lake, under a serial 32 GiB/no-swap systemd scope with `LEAN_NUM_THREADS=2`.

The snapshots retain their actual task-local absolute paths. To regenerate inputs, adjust only the output/input directory paths in the build-only generator and controls, then `lake build SourceReplayMatrix SourceReplayControls`. Compare regenerated bytes with the retained hashes. The generator imports Mathlib; it is not linked into or timed by the executable. To measure retained packets, extract `inputs.tar.gz` separately and `lake build source_replay_bench`. Set `HEX_RCF_SOURCE_REPLAY_INPUT` to one packet and invoke `.lake/build/bin/source_replay_bench run SourceReplayBench.replayed --export-file output.json`; the other arms are `lexical`, `parsed` and `restored`.

`collector.py.txt` records the exact fixed five-block protocol, automatically leased CPU placement and per-child resource accounting. Reuse requires updating the checkout/project/input/output paths and choosing a fresh output directory, not overwriting this record. Result consumption, IO.Ref reads and hashing remain inside timed batches; process startup, file loading, generation and proofs remain outside per-call times. Each invocation includes a warmup and one autotuned outer sample. Repeated study execution is a new collection, not part of these 440 observations.

The raw benchmark exports identify the external harness checkout in their git metadata; `context.json` identifies the actual Hex source checkout. Neither the historical paths nor that external git identity should be confused with the measured Hex source pin. `analyze.py.txt` records the analysis and plotting code; its original task paths require adaptation. No timing subtraction, matched speedup or asymptotic scaling claim is made.

The SVG export's trailing line whitespace is removed for the repository whitespace check; `dimensions-original.svg.gz` preserves the unmodified plotting output and `normalize-figure.py.txt` records that textual cleanup. The PNG and measured observations are unchanged.
