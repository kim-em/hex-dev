# Stored-row and dependent replay quotation

`RowQuote.decoder` reads the stored integer in a checked selected-sign row.
Ordinary equality laws preserve its array through query equality, descriptor
retargeting and restoration of supplied operations. The decoder preserves the
actual operation instances and checks each proposed array, value and Boolean
equality against its original target. It does not run a sign producer or add a
solver handler. Unknown boundaries decline; recognized malformed rows fail.

`RootQuote` also abstracts closed helpers whose types depend on a protected
replay function before converting an enclosing Boolean expression. The
original reader must expose that function. A hidden reader retains its
structured boundary rejection and complete caller restoration.

## Limits and remaining work

The preceding complete original-source run advanced past the stored-row
projection but failed when a dependent proof helper retained the concrete
replay function during abstraction. Its full log and exact input sources are
retained. It did not establish complete packet acceptance or the source goal.
The new focused Boolean-helper controls reproduce and repair that boundary.
A subsequent full production run is outside this immutable focused record
until it terminates; this report claims no complete source proof from it.

This is a correctness and bottleneck investigation, not a scaling study or
matched AB/BA comparison. Charged nodes and compiled module bytes do not
measure physical sharing or serialized certificate size. In particular, the
same public-packet fixture changes from 1,183,543 to 1,209,665 nodes; comparing
that fixture with the distinct 154,369-node sign-packet fixture would be
invalid. No general speedup is claimed.
