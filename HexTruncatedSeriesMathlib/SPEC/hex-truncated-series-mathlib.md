# hex-truncated-series-mathlib (Mathlib correspondence for truncated series)

`hex-truncated-series-mathlib` is the correspondence-only companion to
[hex-truncated-series](../../HexTruncatedSeries/SPEC/hex-truncated-series.md).
The core library owns the fixed-length coefficient representation and every
executable operation. This layer equips that representation with Mathlib's
`CommRing` API, identifies it with `PowerSeries R` modulo `X ^ n`, and proves
that truncation commutes with the core operations wherever Mathlib supplies a
matching power-series construction.

## Scope

The layer owns no executable algorithm, reifier, certificate checker, or
tactic. Its public surface is:

- the Mathlib `CommRing (TSeries R n)` instance, pinned to the executable
  operations from the core library;
- truncation from `PowerSeries R`, the induced surjective ring homomorphism,
  its kernel, and the resulting quotient equivalence;
- coefficient, constant, variable, power, precision-change, and derivative
  correspondence;
- correspondence for inverse, substitution, reversion, exponential, and
  logarithm;
- existence and uniqueness of a power-series square root above a supplied
  invertible constant root; and
- the construction of `NatInverses R m` from an `Algebra ℚ R` instance.

No theorem solely about `TSeries` belongs here. Such theorems, including the
functional equations for `exp`, `log`, composition, inverse, square root, and
reversion, belong in the Mathlib-free core.

## Principal quotient equivalence

For a commutative ring `R`, coefficient truncation is a surjective ring
homomorphism whose kernel is the ideal generated by `X ^ n`.

```lean
/-- Truncation of a power series to precision `n`. -/
noncomputable def ofPowerSeries [CommRing R]
    (f : PowerSeries R) : TSeries R n

theorem coeff_ofPowerSeries [CommRing R] (f : PowerSeries R)
    (i : Nat) (hi : i < n) :
    (ofPowerSeries (n := n) f).coeff i = PowerSeries.coeff i f

noncomputable def ofPowerSeriesHom [CommRing R] :
    PowerSeries R →+* TSeries R n

theorem ofPowerSeriesHom_surjective [CommRing R] :
    Function.Surjective (ofPowerSeriesHom (R := R) (n := n))

theorem ker_ofPowerSeriesHom [CommRing R] :
    RingHom.ker (ofPowerSeriesHom (R := R) (n := n)) =
      Ideal.span {(PowerSeries.X : PowerSeries R) ^ n}

noncomputable def quotEquiv [CommRing R] :
    (PowerSeries R ⧸ Ideal.span {(PowerSeries.X : PowerSeries R) ^ n})
      ≃+* TSeries R n
```

The defining computation rule for the equivalence is part of the public
contract:

```lean
@[simp] theorem quotEquiv_mk [CommRing R] (f : PowerSeries R) :
    quotEquiv (R := R) (n := n) (Ideal.Quotient.mk _ f) =
      ofPowerSeries (n := n) f
```

This theorem keeps callers from unfolding the transport through
`Ideal.quotEquivOfEq` and `RingHom.quotientKerEquivOfSurjective`. Together
with `coeff_ofPowerSeries`, it pins the headline equivalence coefficientwise.

The companion builds Mathlib's `CommRing (TSeries R n)` directly from the
executable operations. Mathlib deliberately provides only the forward bridge
from `CommRing` to `Lean.Grind.CommRing`; reconstructing a Mathlib ring through
that bridge would not definitionally preserve the core subtraction and
negation used by callers.

## Structural correspondence

The ring equivalence supplies the ordinary `map_zero`, `map_one`, `map_add`,
`map_neg`, and `map_mul` laws. The following named theorems cover operations
whose correspondence is not just a generic `RingHom` projection:

```lean
theorem pow_eq_mathlib [CommRing R] (a : TSeries R n) :
    ∀ k : Nat,
      Hex.TSeries.pow a k = (commRing (R := R) (n := n)).npow k a

theorem ofPowerSeries_pow [CommRing R] (f : PowerSeries R) (k : Nat) :
    ofPowerSeries (n := n) (f ^ k) =
      Hex.TSeries.pow (ofPowerSeries (n := n) f) k

theorem ofPowerSeries_C [CommRing R] (r : R) :
    ofPowerSeries (n := n) (PowerSeries.C r) = Hex.TSeries.C r

theorem ofPowerSeries_X [CommRing R] :
    ofPowerSeries (n := n) (PowerSeries.X : PowerSeries R) = Hex.TSeries.X

theorem truncate_ofPowerSeries [CommRing R] (f : PowerSeries R)
    {m k : Nat} (hkm : k ≤ m) :
    (ofPowerSeries (n := m) f).truncate k hkm =
      ofPowerSeries (n := k) f

theorem mulXPow_ofPowerSeries [CommRing R] (f : PowerSeries R) (k : Nat) :
    (ofPowerSeries (n := n) f).mulXPow k =
      ofPowerSeries (n := n) ((PowerSeries.X : PowerSeries R) ^ k * f)

theorem deriv_ofPowerSeries [CommRing R] (f : PowerSeries R) :
    (ofPowerSeries (n := n) f).deriv =
      ofPowerSeries (n := n - 1) (PowerSeries.derivative R f)
```

`extend` has no power-series-side operation: both `TSeries` values already
come from truncating the same unbounded series, and
`truncate_ofPowerSeries` is the canonical statement. `divXPow?` and
`valuation?` are partial executable inspections whose correctness remains in
the core.

## Newton and substitution correspondence

The witness-taking operations line up with Mathlib under their exact
hypotheses:

```lean
theorem ofPowerSeries_invOfUnit [CommRing R]
    (f : PowerSeries R) (u : Rˣ)
    (hu : PowerSeries.constantCoeff f = u) :
    ofPowerSeries (n := n) (f.invOfUnit u) =
      Hex.TSeries.invOfUnit (ofPowerSeries f) ((u⁻¹ : Rˣ) : R)

theorem ofPowerSeries_subst [CommRing R] (f g : PowerSeries R)
    (hg : PowerSeries.constantCoeff g = 0) :
    ofPowerSeries (n := n) (f.subst g) =
      Hex.TSeries.comp (ofPowerSeries f) (ofPowerSeries g)

theorem ofPowerSeries_substInvOfIsUnit [CommRing R]
    (g : PowerSeries R)
    (h0 : PowerSeries.constantCoeff g = 0)
    (hu : IsUnit (PowerSeries.coeff 1 g)) :
    ofPowerSeries (n := n) (g.substInvOfIsUnit hu) =
      Hex.TSeries.revOfUnit (ofPowerSeries g) ((hu.unit⁻¹ : Rˣ) : R)

theorem ofPowerSeries_exp [CommRing R] [Algebra ℚ R]
    [NatInverses R (n - 1)]
    (f : PowerSeries R) (h : PowerSeries.constantCoeff f = 0) :
    ofPowerSeries (n := n) ((PowerSeries.exp R).subst f) =
      Hex.TSeries.exp (ofPowerSeries f)

theorem ofPowerSeries_logOf [CommRing R] [Algebra ℚ R]
    [NatInverses R (n - 1)]
    (f : PowerSeries R) (h : PowerSeries.constantCoeff f = 1) :
    ofPowerSeries (n := n) (PowerSeries.logOf f) =
      Hex.TSeries.log (ofPowerSeries f)
```

The constant-coefficient hypotheses on inverse and substitution are
essential. Mathlib's `invOfUnit` uses the supplied unit even if it does not
match the series. Mathlib's `HasSubst` permits a nilpotent constant
coefficient, while the core composition contract deliberately requires a
zero constant coefficient.

Mathlib's exponential and logarithm require `Algebra ℚ R`, which is stronger
than the core's precision-indexed `NatInverses R (n - 1)`. The companion
therefore provides a low-priority `NatInverses R m` instance from an
`Algebra ℚ R` but does not narrow the core API to characteristic zero.

## Square roots

Mathlib has no power-series square-root operation matching the core's
supplied-root contract. The companion states and proves the semantic theorem
directly:

```lean
theorem exists_unique_sq [CommRing R] (f : PowerSeries R) (r : R)
    (hr : r * r = PowerSeries.constantCoeff f)
    (hu : IsUnit (2 * r)) :
    ∃! s : PowerSeries R,
      s * s = f ∧ PowerSeries.constantCoeff s = r
```

The statement is uniqueness above one chosen constant root, not a claim that
the coefficient ring has only two roots.

## Verification

The headline equivalence is justified by the surjectivity and kernel
theorems, and `quotEquiv_mk` exposes its action on quotient representatives.
Operation correspondence is proved coefficientwise from Mathlib's
power-series theorems and the core characterizing lemmas. The layer contains
no `sorry`, no axiom, and no runtime appeal to an external oracle.

There is deliberately no conformance module for this library. Each transported
operation is exercised by `conformance/HexTruncatedSeries/Conformance.lean`
and its SymPy fixture oracle under the computational owner.

## External comparators

`correspondence-only-layer`: this library has zero benchmark targets and no
independent executable or proof-search surface to compare. The computational
performance owner is `hex-truncated-series`; its multiplication, inverse,
square-root, exponential, logarithm, composition, and reversion registrations
carry the evidence for every operation transported here.
