# 2026-09-05 issue #9990: packed vertex sets above 63 vertices

Session type: feature (directive #9990).

## Accomplished

- `HexGraphIso/Nauty/VSet.lean`: the packed vertex-set type, `Array Nat`
  limbs each below `2^63` (vertex `v` at bit `v % 63` of limb `v / 63`),
  with the membership, cardinality, iteration, renaming and row-order
  API the search needs, and a `toNat` correspondence layer that
  transports every statement to the `Nat` bitset the kernel-facing
  checker keeps.
- `rowsOf`, `Ctx`, `RefineSt`, `SearchSt` and the whole refine/search
  tree run on `VSet n`; the vertex count is an index of every search
  type, so the `ctx.n` field and the row-bound hypotheses that only
  existed to carry it are gone. The entire theory tree (equitable
  refinement, target cell, small-cell leaves, quartet, search outcome,
  certificate totality, trace agreement) is ported; no `sorry`,
  `axiom` or `native_decide`.
- `NodeLit`'s literal tower stays on `Nat` and consumes packed rows
  through `Ctx.toL` and `KeyL`, with a proof per operation.
- Kernel reducibility across the module boundary: `HexBasic.OfFn` gains
  `Hex.Array.zipWith'` (core `Array.zipWith`'s `zipWithMAux` loop does
  not reduce downstream, like `Array.map`), and `VSet` equality routes
  through `Hex.instDecidableEqArray`. `ModuleBoundaryTests` is green.
- Verification: `hexgraphiso_emit_fixtures` is byte-identical to the
  committed fixture; the 32,798-case campaign agrees with nauty 2.9.3;
  bench, conformance, manual and Mathlib layers build.
- `scripts/bench/graphiso_perf_side_by_side.sh` (perf category table),
  `scripts/bench/graphiso_pernode_fit.py` (per-family exponent fit,
  `--check 0.2` required in the single CI job beside the sweep
  freshness check, also run by the sweep script), the SPEC paragraph
  naming the check, the manual's Performance model paragraph, and
  `reports/hex-graph-iso-packed-sets.md` with before/after profile and
  fit numbers. Sweep refreshed at fingerprint `17852d9b9995`.
- `Families.choose` is multiplicative: the Pascal recurrence was the
  largest symbol in the cactus profile, inside the corpus's lazy
  Kneser/Johnson adjacency functions.

## Numbers

Per-node exponent gap hex minus nauty went from +0.3 to +0.8 per family
to -0.2 to +0.01. Hex/nauty ratio: 5.7 / 18.6 (n ≤ 64 / n > 64)
before, 7.7 / 7.1 after. Instances above 64 vertices are 2.6x faster
(geometric mean); instances below run at 0.74x because a one-limb
array allocates where an unboxed `Nat` did not.

## Decisions

- One representation for every size, no small-graph twin: Kim asked
  for a genuine representation change rather than a csimp seam.
- Limbs are `Nat` below `2^63` rather than `UInt64` or `ByteArray`:
  the same unboxed scalar path as the old small bitsets, with `Nat`
  bit lemmas reusable in the proofs and no boxing at the `Nat`
  boundary of the checker; 63 bits per limb keeps every limb a scalar.
- `Hex.Array.zipWith'` follows the `Array.map'` pattern already in
  `HexBasic.OfFn`; a core fix would make both retire.

## Remaining

- The small-graph slowdown (0.74x below 64 vertices) is measured and
  documented, not addressed.
- `scripts/bench/graphiso_cactus_sweep.sh` assumes `matplotlib` on the
  host Python; on this host the plot leg needs
  `uv run --with matplotlib==3.11.1`.
