# Converge figure-freshness checks on content-fingerprint keying

Session type: feature (issue #9893).

## What landed

`scripts/bench/sweep_freshness.py` is now the single mechanism behind
every merge-CI freshness check for published performance figures. A
`Family` declares the relevant source (include paths, exclusions), the
exemption directory, the required figures and the regeneration command.
From that the module derives the listing (`git ls-files -s`, or the same
bytes reconstructed from a tree with `git ls-tree -r`), the twelve-digit
sha256 fingerprint, the committed manifest, the path-by-path diff and the
exemption lookup.

Both enforced families are ported:

- hex-graph-iso keeps its existing fingerprints byte-for-byte (a unit
  test pins the listing against the historical pathspec, since every
  committed sweep name depends on it), and now emits and diffs against
  manifests. A stale check names the differing paths and their blob
  transitions instead of only reporting a fingerprint miss.
- Factorization drops the `recorded commit..HEAD` diff entirely. Each
  system's newest committed observation carries `env.source_fingerprints`
  and a `hexbz-factor-<system>-<fp12>.manifest`, backfilled from the
  measuring commits while they were still resolvable. The
  proof-only exemption directory carries over unchanged, and the
  lakefile-block rule is passed in as the family's `allow` hook.

## Decisions

- The relevant sets are preserved exactly. A one-off comparison against
  the old `source_path` predicate over every tracked file showed set
  equality for all six systems, so the port cannot change which edits
  are considered runtime-relevant.
- Manifests are only backfilled where the listing is provably the one
  that was measured: the factorization commits (clean trees, recorded in
  the report) and the seven hex-graph-iso sweeps whose recorded
  fingerprint the reconstruction reproduces. The remaining historical
  graph-iso sweeps still match by fingerprint; they just cannot serve as
  a diff baseline.
- Editing `scripts/bench/factor_sweep.py` to record fingerprints moves
  every system's fingerprint, so this pull request writes exactly one
  runtime-neutral exemption for that blob transition. That is the
  mechanism working as designed, not a workaround.

## Not done

The C sources under `<library>/ffi/` reach the factorization binary but
are not in the relevant set, because `Hex/BenchOracle/ffi/` sits in the
same trees and belongs to the oracles. Splitting those apart is a
separate change, noted in a comment next to the declaration.

Whether the scheduled-only comparator figures (LLL, Hermite, Smith)
should adopt merge-CI enforcement is left open, as the issue asked; the
new SPEC section records that the mechanism is available and what
adopting it costs.
