# Accomplished

- Extended atomic instantiation requests with arbitrary scoped propagator
  applications whose anchor, ordered reads, and ordered writes may reference
  either existing expressions or expressions created by the same event.
- Replaced post-instantiation full recompilation with a canonical append-only
  application arena.  Dynamic scopes append before local applications created
  by the same event, while every earlier application identifier, queue bit, and
  policy clock remains stable.
- Added package/session semantic scope validation at both reply retention and
  admission.  The generic engine still owns structural checks and write
  authority; proof replay remains the soundness boundary.
- Recorded exact resolved bindings, application outputs, and fresh subsets in
  instantiation events for later proof replay.
- Propagated application creation generation through actions and policy keys,
  including the scope-only causal chain which previously could evade the
  generation limit.
- Added dedicated scope-size limits, policy traversal accounting, generated
  scope metrics, and exact rollback checks.
- Added conformance canaries for scope-only admission, dynamic CSE, two
  successive mixed scope/local admissions, package vetoes, causal generation,
  watcher and identifier stability, and exact application, queue, and scope
  boundaries.
- Built the experiment umbrella and all affected scheduler, registry, policy,
  dyadic-rule, and scope conformance targets successfully.

# Current frontier

- The scheduler-side arbitrary-propagator framework now supports both static
  and dynamically instantiated nonlocal scopes.  `Engine.applications` is the
  canonical append-only execution arena; `Engine.bindings` is an audit log and
  must not be used to reconstruct dynamic application order.
- The replay/SPEC stack still needs to consume the new resolved binding and
  application provenance and reject forged binding/identifier combinations.
