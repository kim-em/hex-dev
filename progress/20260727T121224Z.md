# Generic interval-propagator framework

## Accomplished

- Added a Mathlib-free experimental engine in which operations are opaque and
  arbitrary external propagators interact through declared inputs, declared
  outputs, and an atomic request/reply protocol.
- Added dependency-indexed scheduling, fact versions, complete provenance,
  bounded structural instantiation, common-subexpression reuse, and exact
  rollback on malformed or over-budget results.
- Made each accepted narrowing depend explicitly on the target's preceding
  fact version, so replay can justify the intersection even when the target is
  not one of the propagator's declared inputs.
- Specified equality propagation as an engine-owned, two-ended contractor and
  policy choice as selection from engine-owned semantic offers. Neither layer
  depends on the meaning of a function operation.
- Retained each structural suggestion's complete triggering action, including
  effort and exact input versions, for instantiation and equality replay.
- Added synthetic conformance cases for forward and backward propagation,
  refinement, coalesced wakeups, several methods for one opaque function, and
  two generations of dynamically introduced expressions.
- Added a scheduler benchmark: after one local refinement, four disconnected
  depth-eight chains require 8 incremental propagator calls rather than 64
  whole-network calls, with identical final facts.
- Revised the interval SPEC to make the generic framework the first
  implementation milestone. Rational and elementary-function arithmetic are
  explicitly plug-ins rather than scheduler foundations.

## Current frontier

The generic protocol and instantiation path build and pass their focused
checks. The SPEC now gives concrete boundaries for equality transport and an
adaptive policy, but the experiment still retains equality edges inertly and
uses deterministic FIFO rather than the engine-owned offer frontier.

## Next step

Implement the unified rule/equality work queue and its atomic two-sided
transport test. Then split FIFO polling into engine-owned offers and an
external policy selection driver. Keep endpoint arithmetic and
function-specific propagators outside the scheduler.
