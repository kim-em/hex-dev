# Minimal polynomial SPEC (issue #9325)

## Accomplished

Wrote `SPEC/Libraries/hex-min-poly.md` for `hex-min-poly` and
`hex-min-poly-mathlib`, and updated `SPEC/Libraries/README.md`,
`SPEC/future-work.md` (the item graduates) and the forward reference in
`SPEC/Libraries/hex-char-poly.md`.

The design, with the parts that were checked against the tree rather
than assumed:

- The order polynomial of a vector comes from one `rowReduce_rank` on
  the `(n+1) × n` Krylov matrix plus one `spanCoeffs` call. The
  prefix-collapse argument (once an iterate is dependent, all later ones
  are) is what makes one rank computation replace a linear search, and
  it is also what discharges the `Option` under design principle 8.
- The matrix minimal polynomial is the lcm over the standard basis.
  Basis-wide coverage is enforced by a length index on the certificate,
  not by a runtime test.
- The certificate carries, per basis vector, a monic order polynomial,
  its annihilation, and a right inverse of the Krylov matrix as the
  independence witness; plus a running-lcm chain whose steps carry
  cofactors and a Bezout pair. It is checked by ring identities and
  matrix-vector products only: no division, no row reduction, no gcd.
- Everything is `mulVec`-only, so no definition needs the `@[csimp]`
  route that `Hex.Matrix.mul` sits behind. Verified by elaborating the
  API shapes.

## Decisions worth carrying forward

- **`deg m_A ≤ n` is not a Mathlib-free theorem in version one.** Each
  `d_i ≤ n`, but lcm degree is not bounded by the max, so the
  Mathlib-free contracts give only `n²`. The true bound is
  Cayley-Hamilton, so it and `m_A ∣ χ_A` are companion theorems and
  `hex-char-poly-mathlib` is a companion dependency. `hex-char-poly` is
  not a computational dependency.
- **The accumulated-span shortcut is wrong as usually stated.** With
  `A = [[0,1],[0,0]]` the relative order polynomials over the standard
  basis are `x` and `x`, whose lcm is `x`, while `m_A = x²`. This is in
  the SPEC, in the conformance list, and in the `#guard` list.
- **A single-vector certificate always exists** (maximal-order argument)
  and would be `n` times smaller. Version one does not use it because
  producing the vector needs a failure branch; recorded as an open
  question, not as an impossibility.

## Confirmed gaps in other libraries

All six confirmed by elaboration, not by grep alone:

- `Lean.Grind.CommRing (DensePoly F)` unreachable without hex-resultant
  (already requested by hex-poly-smith and hex-char-poly).
- `Hex.DensePoly.GcdLaws F` has no generic-field instance (already
  requested by hex-poly-smith).
- `Hex.DensePoly.monicize` absent (already requested by hex-poly-smith).
- `Hex.DensePoly.lcm` absent. This SPEC is the first consumer and takes
  the decision hex-cyclotomic deferred: monic-normalised,
  `lcm p 0 = 0`, `lcmList [] = 1`.
- `Hex.Matrix.vecMul_mul` exists only as an `Int`-only copy under
  `Hex.Internal` in `HexLLL/Lattice.lean`; the generic form follows from
  `mul_assoc_vec` and `transpose_mul_of_mul_comm`.
- `Hex.DensePoly.size_mul` as an equality is proved inside
  `leadingCoeff_mul` and discarded; only `size_mul_le` is exported.
