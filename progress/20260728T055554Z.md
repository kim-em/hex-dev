# Package-owned semantic replay protocol

## Accomplished

- Added a Mathlib-free semantic replay protocol with abstract program models
  and fact meanings, with no central arithmetic or function inductive.
- Added existentially packed, cache-free rule fact schemas whose exact
  dispatch address is `(RuleKey, role, schema)`.
- Separated proof of a rule's proposed fact from a fact-domain schema proving
  that the installed fact denotes exactly the intersection of the previous
  and proposed facts.
- Bound replay contexts to the caller's exact base program, initial facts, and
  target, and added an explicit base-program prefix proposition.
- Added prefix-only trace lookup that cannot inspect a future fact event and
  never reads a mutable current-fact slot.
- Added a canary with two unrelated opaque unary functions. They reuse the
  same local schema number but have distinct rule keys, certificate types,
  body encodings, and theorem packages; the generic dispatcher is unchanged.
- Tested wrong-rule encoding, wrong semantic role, semantic meet evidence,
  future-event isolation, and caller-owned version-zero lookup.
- Built `HexInterval.Experiment.SemanticReplay`,
  `HexInterval.SemanticReplayConformance`, and `HexIntervalExperiment`.

## Current frontier

The generic proof-side package boundary is compile-tested, but it intentionally
does not claim to be a complete trace checker. Rule schemas return real Lean
proofs of semantic consequence, and the fact-domain layer returns real
intersection proofs.

## Next step

Instantiate the protocol in the Mathlib companion for the existing fixed
centered-product example. Then add one forward trace fold that resolves action
inputs only from the checked prefix, combines rule and meet evidence, and
closes the caller's exact target.

## Blockers

The full vertical still needs package-owned instance and equality schemas,
validation that semantic schemas match the immutable search-format snapshot,
checked append-only program extension, chronological event/version validation,
and final target closure. These are explicit protocol obligations rather than
assumed soundness.
