# Release-readiness review of the polynomial factorization libraries

## Accomplished

- Reviewed `HexPoly`, `HexPolyZ`, `HexPolyFp`, `HexBerlekamp`, `HexHensel`,
  `HexLLL`, `HexBerlekampZassenhaus`, and their Mathlib-facing libraries for
  source organization, naming, documentation, proof quality, tests,
  performance evidence, and publication readiness.
- Verified `lake build`, the release-manifest check, the dependency-DAG check,
  and the published trust-surface check. The published surface contains no
  axioms, sorries, or `native_decide`; the headline factorization theorems use
  only the standard `propext`, `Classical.choice`, and `Quot.sound` axioms.
- Found a public-API namespace defect: the documented
  `Hex.ZPoly.Irreducible_iff_polynomialIrreducible` and
  `Hex.ZPoly.isIrreducible_iff` names are actually nested below
  `HexBerlekampZassenhausMathlib.Hex.ZPoly`.
- Checked every package README quickstart. All compile except the `HexLLL`
  quickstart, whose `#eval` commands cannot link the native `Matrix.exactDiv`
  implementation under `lake env lean`.
- Ran the publication dry-run against the live baseline. Existing
  `hex-poly`, `hex-poly-mathlib`, `hex-lll`, and `hex-lll-mathlib`
  repositories pass individual dry-runs, but the full run stops because 13
  repositories in the factorization dependency chain have not been created.
- Identified first-release cleanup debt: explicit compatibility shims,
  software-engineering filenames, broad undocumented API records, long theorem
  names, oversized proof files, global heartbeat overrides, README structure
  violations, project-banned jargon, and phase-history prose in specifications.
- Confirmed the repository still pins `leanprover/lean4:v4.32.0-rc1` although
  stable Lean `v4.32.2` is available.

## Current frontier

The mathematical implementation and proof trust boundary are release-grade.
The public API, package presentation, toolchain pin, and publication bootstrap
are not yet ready for a stable first release.

## Next step

Fix the namespace and README blockers, move to a stable Lean toolchain, remove
the compatibility surface before names become public commitments, then perform
the object-based file/name and documentation pass. Create the missing released
repository skeletons, run a clean full publication dry-run, publish, and verify
fresh standalone clones. Refresh the Hex performance record after the toolchain
change; external comparator records can remain when their host, corpus, and
protocol are unchanged.

## Blockers

- Thirteen required released repositories do not yet exist under
  `leanprover`.
- The documented root `Hex.ZPoly` irreducibility theorem names do not exist.
- The `HexLLL` README quickstart does not compile as required.
- The monorepo is pinned to a release candidate rather than the available
  stable Lean release.
