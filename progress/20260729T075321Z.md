# Arbitrary-scope contractor applications

## Accomplished

- Added explicit start-time bindings for package rules whose reads and writes
  span arbitrary expression nodes rather than one operation's local slots.
- Kept legacy local registration behavior source-compatible and preserved
  application identifiers across append-only program growth by compiling the
  immutable scoped prefix before node-local applications.
- Stored validated bindings in engine state and reused them during expression
  instantiation recompilation.
- Extended package dispatch validation for scoped requests while keeping the
  compiled engine application authoritative for concrete ports.
- Added conformance canaries for ordered nonlocal reads, atomic two-output
  updates, self-revisit coalescing, write-only behavior, unrelated wakeups,
  rollback, write authorization, malformed bindings, exact resource edges,
  and real append-time identifier preservation.
- Built the experiment rollup and the propagator, package-registry, policy,
  policy-driver, and new scope conformance targets successfully.

## Current frontier

The scheduler now executes arbitrary finite start-time contractor scopes.  It
validates structural visibility and authority, while package schemas and proof
replay remain responsible for the mathematical meaning of each scope.

## Next step

Prototype dynamic scoped applications inside instantiation proposals.  New
bindings must resolve atomically with proposed nodes and equalities, append to
the application arena without renumbering existing work, and be recorded by
semantic replay even when a proposal adds no expression node.

## Blockers

None.  An independent framework review is still running in parallel.
