# Bounded structural rule views

## Accomplished

- Added a versioned, immutable `ProgramView` to arbitrary `RuleRequest`s.  It
  exposes the validated operation table, SSA nodes, and instantiation
  generations without exposing any undeclared facts.
- Supplied the same view through both the reference worklist and the checked
  policy-selection request path.
- Added an opaque nested-DAG conformance fixture which recognizes
  `x * (one - x)`, rejects reversed and mismatched lookalikes, and recovers the
  exact existing node identifiers with an empty fact-input list.
- Exercised the matcher again on an append-only generated suffix and checked
  that both a still-fresh pre-extension proposal and the new proposal can be
  revalidated and admitted with their respective generations.
- Updated the SPEC with the current whole-view design and the open alternative
  of compiler-produced structural bindings.
- Passed the focused propagator, policy, frontier, and structure-view builds plus
  copyright, line-count, trust-surface, and whitespace checks.

## Current frontier

Arbitrary instantiation rules can now inspect expression structure without
turning that inspection into unrestricted fact access.  Append-only program
growth gives later requests a new snapshot version, while an older proposal
whose application and watched facts remain fresh can survive and is fully
revalidated against the current program before admission.

## Next step

Use this boundary in concrete nonlinear propagator experiments, then compare
the flexible whole-program view with precompiled shape bindings on large shared
DAGs and repeated program extensions.
