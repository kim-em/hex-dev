# Precision-indexed high-accuracy log table

## Accomplished

- Added a Mathlib-free logarithm provider with explicit precision-request and
  exact-input facts. The bounded provider supports 20- and 50-decimal requests,
  selecting 22 and 53 series terms respectively.
- Added replay payloads that retain and authenticate the precision, term count,
  lower and upper rational endpoints, and source input dependency.
- Proved the endpoint facts from the odd-power `log(1+a)` series at `1/3`, with
  a kernel-checked geometric remainder bound and exact rational normalization.
- Added generic package/session/chronology/`ProofFrontend` conformance yielding
  an ordinary 50-decimal strict enclosure theorem for `Real.log 2`.
- Added a lower-precision trace and replay rejection for insufficient terms,
  wrong endpoint, wrong precision, and wrong source fact, plus a guarded axiom
  report.
- Documented the delivered boundary and the remaining arbitrary-input,
  persistence, caching, batching, ordering, and performance work.
- Built the focused modules and full `HexIntervalExperiment`,
  `HexIntervalMathlibExperiment`, and `HexConformance` targets; trust, static,
  Mathlib-free bench, and diff checks passed.

## Current frontier

Precision now changes a replay-visible numerical recipe rather than selecting
only an opaque theorem. The implementation is intentionally bounded to two
requests for one exact input.

## Next step

Compute endpoint certificates for arbitrary requested precisions and rational
inputs, then add shared persistent table construction, adjacent-entry ordering,
and the 257-entry `log (1 + i/256)` batch benchmark.

## Blockers

None for the bounded 20-/50-decimal provider. The host cache extraction filled
the filesystem during setup; generated cache data was removed and the existing
compatible package/build cache was reused. This did not affect repository
source or proof checking.
